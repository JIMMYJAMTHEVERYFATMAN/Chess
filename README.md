# Offline Chess

A local chess analysis app built with PyQt6, `python-chess`, and Stockfish. Game records and PGNs stay on this computer. With reporting enabled, the app sends an installation check-in containing a random install ID, app version, last-seen time, and saved Chess.com username. You can turn check-ins off in **Profile → Settings**. Bug reports and feature suggestions are sent only when you submit them. Neither feature sends game history or PGNs.

The **Position Lab** tab accepts a FEN and shows Stockfish's top three candidate moves for the selected side to move, with evaluations and principal variations, within the selected time limit.

The **Opening Trainer** tab teaches White and Black repertoire lines from the bundled Lichess opening catalog. Choose an opening and one of its lines to drill your moves while learning the opponent's replies. Saved Chess.com games show your opening results and let you jump into your most-played or lowest-win-rate openings.

The **Endgame Trainer** lets you build an endgame with the board editor or generate a random queen, rook, or pawn ending, then play for checkmate against Stockfish with a selectable Elo.
From Game Review, choose **Practice this game’s endgame** to continue from a position found in the reviewed game.

The **Puzzles** tab offers engine focused tactics, total random puzzles, training based on downloaded Chess.com games and review weaknesses, forced mate challenges, and an escalating challenge run. Each puzzle has three lives. The challenge high score is saved in the local profile and shown in Profile.

## Run the app

Requirements: Python 3.10 or newer, PyQt6, `python-chess`, `cryptography`, and a Stockfish 19 compatible engine.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python main.py
```

The app looks for `stockfish.exe` beside `main.py`. Set the `STOCKFISH_PATH` environment variable if the engine is installed elsewhere.

`build/` and `dist/` are generated by local packaging and should not be edited as source. The release workflow builds the Windows EXE and publishes it with a SHA-256 checksum. User profiles and downloaded Chess.com PGNs are stored under `%LOCALAPPDATA%\OfflineChess`, rather than in the repository.

## Windows EXE and updates

Tagged releases build a single `OfflineChess.exe` that includes Stockfish and the Lichess opening database. The app checks the public GitHub Releases page in the background when it starts. If a newer release is available, it offers to download and install it, verifies the published SHA-256 checksum, then restarts with the new version. Run the EXE from a folder your Windows account can write to, such as Downloads or a folder under your user profile.

To publish a release, update `APP_VERSION` in `offline_chess/config.py`, commit the change, create the matching tag (for example `v1.1.2`), and push the tag. GitHub Actions runs the test suite, builds and publishes the EXE and checksum, license notices, and the corresponding Stockfish source and network files. The release tag must match `APP_VERSION`. Release notes include the matching version section from `CHANGELOG.md`.

To build locally on Windows after installing the runtime dependencies, run `python -m PyInstaller --noconfirm --clean OfflineChess.spec`. The one-file build extracts its engine and opening database into a temporary folder while it runs. Profiles and downloaded games remain in the user's local application data folder, outside the EXE.

Opening names use the [Lichess chess-openings](https://github.com/lichess-org/chess-openings) TSV files in `openings/` (`a.tsv` through `e.tsv`). The profile shows the opening name and its ECO code together, for example `Bird Opening · A02`.

### Owner usage dashboard

The maintainer dashboard is a read-only webpage served on this computer at `http://127.0.0.1:8765`. It reads event files from a local clone of the private telemetry repository. Generate a dashboard keypair with `python generate_dashboard_keys.py`; keep the private key outside Git, and configure the printed public key as `TELEMETRY_PUBLIC_KEY` in the collector. Configure the collector's server-only GitHub token with Contents write access to the private data repository, plus its `DATA_REPOSITORY` and `DATA_BRANCH` settings. After deploying the collector, set the app repository's Actions variable `OFFLINE_CHESS_CHECKIN_URL` to its HTTPS URL. The release workflow embeds that public URL into the packaged app; local runs can override it through the environment.

For local dashboard access, install the dashboard dependency with `python -m pip install -r requirements.txt`, copy `.env.example` to `.env`, set `OFFLINE_CHESS_DASHBOARD_PRIVATE_KEY` to the generated private PEM and `OFFLINE_CHESS_DATA_REPO` to the local clone path, then run `python setup_dashboard_login.py` to choose a local password. The password hash is stored under app data; sign-in sessions expire after 12 hours. Start the page with `python dashboard_server.py`. The dashboard binds only to loopback. Git must be installed and the clone must be able to fast-forward from the private repository. Keep the private key and GitHub write token secret; the desktop app receives neither.

## Board appearance

Choose the board and piece styles in **Profile → Overview**. Board themes include Classic Green, Walnut, Ocean Blue, Soft Violet, Slate, Mint, Crimson, Graphite, Desert, Nordic, Rose, High Contrast, and Monochrome. Piece styles include Tournament, Modern, Letters, Badge, and Bold. The selected styles are saved locally and apply to play, review, and opening boards.

Use **Profile → Settings** to toggle and save sound effects, load Lichess opening TSV files or a weighted Polyglot book, submit a bug report or feature suggestion, change usage check-in sharing, or delete all locally saved game data. Deleting saved game data removes local game summaries, reviews, downloaded Chess.com games and PGNs, and the puzzle challenge high score; app preferences and the saved Chess.com username remain.

## Chess.com game review

Open **Profile → Chess.com**, enter a Chess.com username, then choose **Find archives**. Select a month to browse its games and download selected games or the full month, or use **Download all months** to fetch every available archive. After an initial download, **Update downloaded games** checks only archive months from one month before the latest saved game and adds unseen games, avoiding another full-history download. Only public archives are available through Chess.com's read-only Published-Data API; its archive can lag behind live games. This app is independent and is not affiliated with Chess.com.

Downloaded games are stored as individual PGN files under:

```text
%LOCALAPPDATA%\OfflineChess\chesscom_games\<username>\<YYYY-MM>\
```

Use **Open PGN folder** to browse them. Opening names use Chess.com's ECO URL when present (including the `ECOUrl` PGN header as a fallback), with the bundled Lichess opening catalog used to normalize names. The dashboard keeps Chess.com's optional per-game accuracy values separate from local Stockfish review accuracy; games without a Chess.com accuracy value are excluded from that metric. Local accuracy uses a nonlinear, CAPS2-inspired grade based on engine evaluation losses; it is not a literal expected-score percentage or a reproduction of Chess.com's proprietary formula. Re-download older games to populate the value when Chess.com has calculated it. Opening mastery estimates how many of your moves remain in the loaded Lichess opening lines before your first departure. The table lists all detected openings by color for the selected period, with per-line book depth and sample size; select a row to chart monthly results and local opening-phase review accuracy, or double-click to filter its games. Chess.com's own book can differ. Tactical review examples can also be double-clicked to run a fresh review and jump to the position. Tactics summarize found forks, pins, checkmates, and opponent pieces newly left hanging; missed fork, pin, and mate chances; and pieces either player leaves hanging or checkmates allowed in current local reviews. Game-flow patterns include each pattern's share of reviewed games with a usable evaluation trace and a selectable average user-side expected-score trace. Move quality over time shows monthly proportions for major quality bands across reviewed moves. The Chess.com profile combines a game library with an Insights-style dashboard: score and win rate, monthly results and both accuracy trends, rating history, performance by time control, color, opponent rating and self-reported opponent country, termination, day and local time, opening results by color with opening-phase accuracy, review coverage, accuracy by game phase and move number, piece accuracy, castling results, move classifications, tactical patterns, and recurring lessons. In **Castling timing and results**, **Quick scan** reads saved PGNs to find each game's first castle. Opening results split moves 3–6 into separate buckets, with earlier and later opening castles grouped separately; middlegame, endgame, and no-castle games have their own rows. The scan does not run Stockfish, and its results are saved for later dashboard refreshes. Select **Lookup opponent countries** to fetch public player-profile country data for opponents; lookups run serially, are cached locally, and can be stopped. Recent period filters also compare score and both accuracy measures with the preceding period. Rating expectation uses an Elo formula as a model baseline, not a similar-player benchmark. Game-flow patterns are local estimates from engine review traces, not Chess.com labels. The period and time-control selectors scope the dashboard and rating history. A result-based performance Elo estimate appears when at least eight rated results have opponent ratings; it is not an official Chess.com rating. Review metrics use the current analysis version, so saved reviews must be refreshed after analysis changes before their measures appear in current profile comparisons.
